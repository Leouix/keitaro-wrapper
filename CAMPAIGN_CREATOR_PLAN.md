# Создатель кампаний Keitaro — план реализации

Дата: 2026-11-18. Автор: Ada (Tech Lead). Проверено на живом tlgk.host.

## 1. Что уже есть

Обёртка `/home/leouix/apps/keitaro` сейчас только читает Keitaro:

- `GET /api/campaigns?query=` — живой поиск кампаний по имени;
- `GET /api/campaigns/{id}`, `GET /api/campaigns/{id}/streams` — карточка и потоки;
- local-first правка оферов в потоке (`/api/campaigns/{cid}/streams/pending`, `/apply`);
- ключ хранится в `.keitaro_api_key` (вводится через UI), клиент — `app/keitaro.py`, база `/admin_api/v1`.

Новая задача — не читать, а создавать кампанию из трёх входных значений: **название, гео (список стран ISO-2), ID оффера**, с готовыми доменом, группой и источником. Стран в кампании может быть несколько: это один фильтр `country` с массивом кодов, отдельные потоки на каждую страну не нужны.

## 2. Проверено живьём (2026-11-18)

Полный сценарий прогнан дважды на одноразовых кампаниях, обе убраны в архив:

1. `POST /campaigns` со `state=disabled` + `group_id`, `traffic_source_id`, `domain_id` → кампания создана, поля применились;
2. `POST /streams` (regular, `schema=redirect`, фильтр `country/accept/["KZ"]`, `action_payload=https://google.com`); массив стран фильтр принимает целиком — в аккаунте уже есть кампании с `["AU","MX"]`;
3. `POST /streams` (default, `schema=landings`, `offers=[{offer_id, share:100}]`);
4. `POST /campaigns/{id}/enable` → `state=active`;
5. `DELETE /campaigns/{id}` → `state=deleted`, `GET` отдаёт 404.

Фактические данные аккаунта: домен `1813 kylovoa.com`, группа кампаний `10332 FORTESTS`, источник `836 FORTESTS`; групп кампаний 15, домен 1, источник 1.

Важно: рабочий API — legacy `/admin_api/v1` (новый `/admin/api/v1` по-прежнему отдаёт 403 по IP). Swagger: <https://admin-api.docs.keitaro.io>.

## 3. Эндпоинты, которые нужны

| Метод | Путь | Зачем | Статус ключа |
|---|---|---|---|
| GET | `/campaigns` | проверка дубля по имени | ок |
| POST | `/campaigns` | создать кампанию (`alias`, `name` обязательны) | ок |
| POST | `/campaigns/{id}/enable` | включить после сборки потоков | ок |
| DELETE | `/campaigns/{id}` | компенсация: убрать в архив при сбое | ок |
| GET | `/campaigns/{id}/streams` | проверка результата | ок |
| POST | `/streams` | создать поток (фильтры/офферы внутри) | ок |
| GET | `/offers/{id}` | показать имя оффера, проверить состояние | частично: часть офферов 403 |
| GET | `/domains` | список доменов для формы | ок |
| GET | `/groups?type=campaigns` | список групп | ок |
| GET | `/traffic_sources` | список источников | ок |
| GET | `/stream_filters` | справочник фильтров (`country` есть) | ок |
| POST | `/domains`, POST `/traffic_sources` | не нужны: берём существующие | 403 |

Ключ не умеет создавать домены/источники и не видит отдельные офферы — для MVP это не блокер, но если понадобится создавать домены из интерфейса, Льву нужно выпустить ключ с правами Domains/TrafficSources/Offers.

## 4. Полезная нагрузка (проверена)

Кампания:

```json
{
  "name": "leo_kz_offer_123",
  "alias": "a1B2c3",
  "type": "position",
  "state": "disabled",
  "group_id": 10332,
  "traffic_source_id": 836,
  "domain_id": 1813,
  "cost_type": "CPC",
  "cost_value": 0
}
```

Alias генерируем сами: 6 символов `[A-Za-z0-9]` (как делает Keitaro), проверяем на дубль не нужно — Keitaro сам отклоняет занятый.

Поток 1 — гео → Google:

```json
{
  "campaign_id": 1,
  "type": "regular",
  "name": "Geo KZ,UZ -> Google",
  "position": 1,
  "action_type": "http",
  "action_payload": "https://google.com",
  "schema": "redirect",
  "collect_clicks": true,
  "filters": [{"name": "country", "mode": "accept", "payload": ["KZ", "UZ"]}]
}
```

Поток 2 — оффер (default, ловит всех остальных):

```json
{
  "campaign_id": 1,
  "type": "default",
  "name": "Offers",
  "position": 2,
  "action_type": "http",
  "schema": "landings",
  "collect_clicks": true,
  "offers": [{"offer_id": 123, "share": 100}]
}
```

Существующие кампании в аккаунте используют ровно эту схему (`regular` с `country` + `default` с офферами), поэтому новый «создаватель» не вводит новый паттерн.

## 5. Порядок операций и сбойные сценарии

```
validate inputs
  → POST /campaigns (state=disabled)
  → POST /streams (geo/redirect)
  → POST /streams (default/landings + offer)
  → POST /campaigns/{id}/enable
  → 201 {campaign, streams}
```

- Кампания создаётся **выключенной**: пока потоки не собраны, трафик по ссылке не пойдёт.
- Любая ошибка после создания кампании → `DELETE /campaigns/{id}` (в архив), ответ с указанием шага (`campaign`/`geo stream`/`offer stream`/`enable`). Если не удалось и это — вернуть 502 с id кампании и текстом «уберите вручную».
- **Ретраи**: текущий `KeitaroClient._request` ретраит сеть/5xx и для POST — для создания это даёт дубли. Для write-вызовов создавателя ставим `retries=0` (или отдельный флаг), фронт защищает от двойного клика.
- Дубль имени: перед созданием ищем точное совпадение в `GET /campaigns`; если есть — 409 с id существующей кампании, фронт спрашивает «Всё равно создать» (`confirm_duplicate=true`).

## 6. Контракт обёртки

`GET /api/campaign-options` → списки для формы:

```json
{
  "domains": [{"id": 1813, "name": "kylovoa.com", "state": "active"}],
  "groups": [{"id": 10332, "name": "FORTESTS"}],
  "sources": [{"id": 836, "name": "FORTESTS"}]
}
```

`POST /api/campaigns`:

```json
{
  "name": "leo_kz_offer_123",
  "geos": ["KZ", "UZ"],
  "offer_id": 18813,
  "domain_id": 1813,
  "group_id": 10332,
  "traffic_source_id": 836,
  "confirm_duplicate": false
}
```

Ответ 201:

```json
{
  "campaign": {"id": 214213, "name": "...", "alias": "a1B2c3", "url": "https://kylovoa.com/a1B2c3", "state": "active"},
  "streams": [{"id": 1, "name": "Geo KZ,UZ -> Google"}, {"id": 2, "name": "Offers"}]
}
```

Коды: 422 — невалидный ввод (имя пустое/длиннее 255, `geos` пуст или содержит не ISO-2, `offer_id <= 0`); 409 — дубль имени; 403 — нет прав у ключа (текст Keitaro отдаём как есть); 502 — Keitaro недоступен/сбой шага. `geos` нормализуем: верхний регистр, без дублей, порядок сохраняем, максимум 20 стран; минимум одна.

Клиент в `app/keitaro.py`: `create_campaign`, `create_stream`, `enable_campaign`, `archive_campaign`, `get_domains`, `get_campaign_groups`, `get_traffic_sources`. Для write-вызовов нужен режим «показать текст ошибки Keitaro» (сейчас 400/422 схлопываются в `Keitaro returned 400`), не меняя поведение существующих read-роутов.

## 7. Интерфейс

- Новый маршрут `/campaigns/new`; после ввода API key ведём сразу туда, поиск кампаний остаётся отдельной страницей (ссылка «Найти кампанию»).
- Форма: название, гео — мультивыбор стран (подсказки ISO-3166 alpha-2 + названия, выбранные страны видны чипами, каждую можно убрать, минимум одна), ID оффера (+ опциональная проверка и показ имени через `GET /api/offers/{id}`), селекты домена/группы/источника из `/api/campaign-options`.
- Дефолты: единственные доступные домен/источник подставляются, группа — `FORTESTS`; последний выбор запоминается в localStorage.
- Состояния: загрузка справочников, отправка (кнопка заблокирована, `aria-busy`), успех (ID, alias, ссылка на кампанию, кнопка «Открыть потоки» → существующая страница потоков), ошибки по коду, 409 — диалог подтверждения дубля.
- Доступность: `<label>` у всех полей, фокус на ошибке, тексты ошибок человеческие («Keitaro недоступен», «Нет прав у ключа», а не код 502).

## 8. Тесты и приёмка

Backend (MockTransport, без живого Keitaro):
- payload кампании: `state=disabled`, домен/группа/источник на месте;
- поток 1: `country/accept/["KZ","UZ"]` (порядок и состав как в запросе), `redirect`, `https://google.com`;
- поток 2: `default`, `landings`, оффер `share=100`;
- `enable` вызывается последним, ровно один раз;
- сбой на потоке 2 → `DELETE` кампании, ответ 502 с шагом; при успехе `DELETE` нет;
- ретраев на POST нет;
- 409 на дубль, 422 на пустой/невалидный `geos`, имя, `offer_id`, 403 с текстом Keitaro; дубли стран схлопываются.

Frontend: пустая форма, невалидное гео, добавление/удаление страны чипом, успешный сабмит (ссылка и ID), 409-подтверждение, 403/502, защита от двойной отправки.

Живой smoke (Rigel, после согласия Льва на запись в Keitaro): одноразовая кампания `__smoke_<дата>`, оффер 18813 (доступен ключу), проверка двух потоков через API, затем архив и проверка 404.

Критерий готовности: из формы создаётся включённая кампания с ровно двумя потоками и выбранными доменом/группой/источником; при искусственном сбое на втором потоке в Keitaro не остаётся включённой полусобранной кампании; все проверки зелёные.

## 10. Допущения (поправить, если не так)

- В кампании может быть несколько стран (проверено на живых кампаниях: один фильтр `country` с массивом кодов); верхняя граница 20 стран — защита от случайной простыни.
- Редирект первого потока — `https://google.com`.
- Оффер встаёт одним потоком с долей 100%.
- Названия потоков: `Geo <XX> -> Google` и `Offers`.
- Домен/группа/источник выбираются из существующих, новые не создаём.
- После входа главный экран — создание кампании, поиск остаётся вторичным.
